# reporter — план развития

## Назначение сервиса

`reporter` формирует разные типы выгрузок (отчётов):

- строит данные выгрузки и рендерит файл (CSV/XLSX/…);
- складывает файл во внешний S3 и отдаёт ссылку в админ-панель / на фронт;
- внутри есть планировщик, который планирует все выгрузки;
- пользователь через админ-панель создаёт расписание для каждого типа выгрузки;
- по расписанию выгрузка регулярно формируется, после готовности сервис уведомляет админ-панель, чтобы та отправила нотификацию о готовности.

## Архитектурные решения

- Go-сервис на платформе `platform` (по образцу `accounter`); gRPC-контракт — в репозитории `contracts`.
- Layout **feature-first** (в отличие от layer-first у accounter): пакеты названы по домену, а не по техническому слою. Каждый тип выгрузки — отдельный пакет.
- Ядро масштабируемости — реестр типов выгрузок + единый конвейер. Новый тип выгрузки = пакет в `reports/`, реализующий `report.ReportType`, и одна регистрация в реестре. Конвейер не меняется.
- Генерация асинхронная: запрос/расписание создаёт джобу, воркер строит выгрузку, заливает в S3, уведомляет.

### Хранилища (dual-store)

- **ClickHouse** (`source`) — источник аналитических данных выгрузок, read-only.
- **MySQL** (через `platform app.Db()`) — операционные метаданные: статусы джоб, расписания, ссылки на готовые файлы в S3. (ClickHouse плохо переваривает частые update'ы строк.)

### Точки расширения (пакеты)

```
internal/
  transport/grpc/   gRPC-хендлеры (тонкие)
  middleware/       gRPC middleware (логирование)
  report/           ReportType + Registry — реестр типов выгрузок
  reports/          реализации конкретных выгрузок (по пакету на тип)
  formatter/        Formatter — рендер Dataset в файл (CSV/XLSX/PDF)
  storage/          Storage — заливка файла в S3 и выдача ссылки
  source/           Source — источник данных (ClickHouse), read-only
  scheduler/        менеджер расписаний поверх platform/servers/scheduler
  service/          оркестрация конвейера
  repository/       доступ к метаданным (MySQL): джобы, расписания
  notifier/         уведомление админ-панели о готовности
```

### Конвейер выгрузки

```
запрос / расписание
  → registry.Get(code) → ReportType.Build(ctx, params)   (запрос в ClickHouse)
  → Formatter.Render(dataset)                             (CSV/XLSX/…)
  → Storage.Put(object)                                   (S3, возвращает ссылку)
  → сохранение метаданных джобы (MySQL)
  → Notifier → админ-панель                               (нотификация о готовности)
```

### Конвенции

- Без комментариев в коде / proto / конфиге.
- Порты: gRPC `40021`, healthcheck `40020`.
- Модуль: `git.bububla.com/kilogramix/asia/reporter.git`.

### Текущее решение по БД

БД пока не подключаем на уровне функционала: нет миграций, репозиториев и запросов. Но `platform app.New` всегда открывает gorm-подключение к MySQL на старте и паникует без неё — поэтому секция `database` в `config.yaml` остаётся, и для локального запуска нужен поднятый dev-MySQL (`make docker_up`). Фактическая работа с БД (метаданные джоб/расписаний) — это этап 2.
